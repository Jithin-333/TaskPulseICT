# TaskPulse Project Architecture

TaskPulse is a centralized Flask application designed for project management, risk analysis, and team analytics. This document outlines the system's modular logic, data flow, and core components.

## 📁 Directory Structure

- `app.py`: The single-file entry point containing the Flask app, routes, business logic, and visualization engine.
- `static/`: Contains CSS, JS, and image assets.
- `templates/`: HTML Jinja2 templates for the frontend.
- `instance/`: Holds the `taskpulse.db` SQLite database.
- `uploads/`: Temporary storage for resume files during analysis.
- `venv/`: Python virtual environment.

## 🧩 Functional Modules

Although implemented within a monolithic `app.py`, the system is functionally divided into several key modules:

### 1. Database & Data Layer
- **Technology**: SQLite3 with dedicated row wrappers (`RowObj`, `ProjectObj`, `UserObj`).
- **Logic**: Directly interacts with `taskpulse.db`. Uses `sqlite3.Row` for dictionary-like access.
- **Key Functions**: Functions prefixed with `db_` (e.g., `db_get_task`, `db_create_project`) handle all CRUD operations.

### 2. Authentication Module
- **Technology**: Flask-Login + Werkzeug Security.
- **Features**: 
    - Role-based access control (Manager vs. Member).
    - Password hashing using `pbkdf2:sha256`.
    - Session management for persisted logins.

### 3. AI Risk Prediction Engine
- **Technology**: Pandas & NumPy.
- **Core Logic**:
    - **Risk Computation**: Compares real progress against expected progress (based on time elapsed vs. total timeline).
    - **Health Score**: Aggregates risk levels across all project tasks to generate a project-wide health metric (0-100).
    - **Insight Generation**: Dynamically creates actionable alerts (e.g., "Task X is 30% behind schedule") based on gap analysis.

### 4. Analytics & Visualization Engine
- **Technology**: Matplotlib (using `Agg` backend for web-safe rendering).
- **Visuals**:
    - **Gantt Chart**: Visualizes task timelines and overlaps.
    - **Burndown Chart**: Tracks ideal vs. actual task completion over time.
    - **Risk Distribution**: Donut charts showing the ratio of Low/Medium/High risk tasks.
    - **Employee Workload**: Comparative analysis of assigned vs. completed tasks per team member.
- **Rendering**: Charts are generated on-the-fly, converted to Base64 strings, and injected directly into HTML templates.


## 🔄 Data Flow

1. **Input**: User interacts with the dashboard (creating tasks/projects) or uploads a resume.
2. **Persistence**: Data is stored in SQLite.
3. **Analysis**: Upon request (e.g., viewing a project), `app.py` fetches raw data and passes it through the **AI Risk Engine**.
4. **Visualization**: The resulting metrics and charts are generated by the **Analytics Engine**.
5. **Output**: Flask renders the final HTML page with embedded insights and charts.

## 📡 API Endpoints

- `GET /api/notifications`: Returns a JSON list of active risk alerts for the manager.
- `GET /api/task_summary`: Provides high-level task statistics.
- `POST /task/update_progress/<id>`: AJAX-based endpoint for updating task completion percentages.
